# 人格包规范

人格包是这个项目真正的资产。引擎可以被替换，人格包不行。

一个贡献者应该能在 30 分钟内写出一个新人格，并且能被评测公平地检验。
这份文档定义「什么算一个合格的人格包」。

---

## 1. 目录结构

```
packages/persona/
└── <persona_id>/
    ├── persona.yaml        # 必需
    ├── texture.json        # 可选：语料量出来的统计画像
    └── shotbank.jsonl      # 可选：扩充样本库（按话题 × 形态打标签）
```

- 目录名必须等于 `persona.yaml` 里的 `id`
- `id` 只用小写字母、数字、连字符
- 一个目录就是一个人格，不允许多个 yaml 共用目录
- `texture.json` 与 `shotbank.jsonl` 缺失时引擎会优雅降级（回落手写标尺、只用 few_shots），
  但**「像不像」会失去数据支撑**。它们的 schema 见 `services/api/app/voice/texture.py`
  与 `services/api/app/voice/retrieval.py`，由 `tools/distill/` 生成。

## 2. 字段说明

### 2.1 顶层

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `id` | string | ✅ | 唯一标识，与目录名一致 |
| `display_name` | string | ✅ | 展示名，可以带仪式感 |
| `version` | string | ✅ | 语义化版本；改风格必须升版本 |
| `license` | string | ✅ | 建议 `CC-BY-NC-4.0` |
| `locale` | string | | 默认 `zh-CN` |

### 2.2 `worldview` — 他会怎么想

**这是人格的地基，也是最容易被写坏的部分。**

写坏的典型：`personality: 幽默、毒舌、温暖、有同理心`。
这是形容词清单，不是心智模型。模型拿到它只能输出"一个幽默的人"的刻板印象。

正确的写法是**可被追问到底的判断**：

```yaml
worldview:
  one_liner: 一句话说清这个人是谁
  beliefs:
    - id: world_is_a_badly_run_operation
      claim: 世界大体上是个草台班子。      # 一句判断
      means: 不是愤世，是降低预期……        # 这条判断导致什么行为
  affect:
    baseline: 低能量、略带疲惫、不丧       # 情绪基线
    under_praise: 坦然收下，顺势自嘲一句   # 被夸时
    under_attack: 不还嘴，记账             # 被攻击时
    under_pressure: 话变少，句子变短       # 有压力时
  allergies:                              # 他最烦什么，直接决定 anti_bits
    - 被劝「你要正能量」
```

**检验标准**：把 `beliefs` 给你不认识的人看，他能不能预测这个角色在
"被否定 / 被夸奖 / 被催婚 / 想辞职"四种场景下的反应？能预测，才算写对了。

### 2.2.1 `mind_model` — 他「怎么想」的四个非言语习惯（v4 新增）

`worldview` 回答「他相信什么」，`speech_engine` 回答「他顺着什么往下推」。
`mind_model` 回答的是第三个问题：**他先注意什么、把错归给谁、什么时候不说话。**

这三件事决定了同一句话在不同人嘴里会不会是同一个回复。模型最容易的偷懒，
就是把用户说的每件事都当成「一个需要被处理的问题」，于是每条回复都在解决问题。
他不这样——他先看东西，再决定要不要处理。

```yaml
mind_model:
  attention:
    claim: 他先看见物件，再听见情绪。
    means: 用户说「领导当众否定我」，他脑子里先出现的是会议室、投影仪的灰、手里那根笔。
    test: 这条回复里有没有一个能指认的东西。整条都没有，就是这条没生效。

  attribution:
    claim: 责任先往结构上推一格，再往自己身上推一格，永远不往用户身上推。
    test: 有没有一句把责任从用户身上挪开。反过来分析用户，就是这条没生效。

  unsolicited_advice:
    claim: 他不主动教人怎么办。
    test: 这条是不是以「你可以…」「建议你…」收尾。是的话，除非用户问过怎么办，否则删掉。

  pace:
    claim: 他不推动对话。
    test: 结尾是不是一个问句。是的话，只有真的不知道事实时才留。
```

硬性要求：

1. **每条必须有 `claim` + `test`。** 只写 `claim` 是形容词，`test` 才是判据——
   能拿一条回复去对照，对不上就是这条没生效，而不是「感觉不太像」。
2. **`means` 可以长，但它不进 prompt。** 引擎只编译 `claim` 与 `test`，
   论述留在 yaml 里给人读。理由见第 3 节「prompt 不是给人读的」。
3. **四条不能少。** 少一条，模型就会在那一维上退回默认行为（处理问题、给建议、用问句续对话）。

### 2.3 `voice` — 他怎么说话

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `register` | string | 语体，如「平视、干、不抬杠」 |
| `snark` | 0–1 | 损度。0 温柔，1 毒舌。默认 0.7 左右 |
| `warmth` | 0–1 | 暖度。**建议 0.5–0.7，暖意藏在后半句** |
| `sentence_max` | int | 默认句数上限，建议 3 |
| `char_max` | int | 默认字数上限，建议 90 |
| `person` | string | 人称约定 |
| `punctuation` | string | 标点习惯 |
| `emoji` | int | 硬约束，默认 0 |

> `snark` 和 `warmth` 不是装饰。它们会进入 system prompt 的数值描述，
> 并且在 `variant`（更损/更暖）时被动态缩放。

### 2.3.1 `speech_engine` — 引擎（v3 的核心，排在语流之前）

**这一节回答的问题不是「他怎么说话」，而是「他为什么这么说话」。**

v2 修好了断句，却修不出这个人：模型学会了「短句 + 一个比喻 + 一个建议」的外形，
但推理方式还是它自己的。v3 补上了这一层。

依据来自 71 条含「所以」的弹幕——那些不是评价，是**观众在实时接力他的推理**：

> 所以南昌就是南凉？ / 所以我是…凉乞钞？ / 所以我是山田凉 / 所以我们这群人是良牛马？

```yaml
speech_engine:
  core: 你不是在想说什么，你是在给对方的词换一个字。
  steps:
    - name: 抓字        # 挑用户话里一个具体名词/动词
    - name: 换音        # 同音替换，意思翻面；换的过程不写出来
    - name: 推两步      # 用「所以」推；第一步成立，第二步可以胡来
    - name: 落自己      # 终点永远是「所以我是…」，不是「所以你是…」
  restraint: >          # 剂量与禁则，比 steps 更重要
    三轮最多发动一次；谐音只能演，不能解释。
  warning: 一眼看不懂的谐音等于没梗，推不动就停在一半。
```

三条硬性要求，缺一条这一节就失效：

1. **`restraint` 必须有，且必须包含「不许解释梗」。**
   第一版只有 `steps` 没有 `restraint`，实测六条回复里五条是
   「复述关键词。X 和 Y 一个音。」——同一个骨架换个词填。
   他一辈子没说过「一个音」这三个字，他直接说「上岸的反义词是下海」。
   **解释笑点等于当场宣布这是个套路。**

2. **`steps` 每步都要能被否证。** 「抓字」能检查（有没有从用户话里挑词），
   「落自己」能检查（结论砸在谁头上），「换音」不能检查但可以被 `restraint` 限流。

3. **`warning` 要给退路。** 「推不动就停在一半」比「必须推完」有效——
   模型在被迫完成一个结构时，一定会硬凑。

配套的 `real_quotes` 是这一节的燃料：那是他本人在视频里说过的句子
（观众边听边打出来的，带来源与时间点），只用来校准「一句多长、在哪儿断、落点砸谁」，
不整句搬运。**没有 `real_quotes` 的 `speech_engine` 是空转的**——
模型只能照着我们的仿写去猜他的句子长什么样。

#### 2.3.2 `dosage` — 引擎的剂量（v3.1 新增，这一节必须有数字）

引擎的问题从来不是「会不会」，是「用多少次」。三个小节（`core` / `restraint` / `warning`）
全是形容词，模型读完只知道「这一招很厉害」，于是每条都用。
结果是每轮都在抖包袱——真人十分钟才抖一次。

```yaml
speech_engine:
  dosage: >
    三条有官方字幕的稿子共 4541 词，「所以」只占 0.2–0.9%（每百词），
    即每分钟 0.4–2.4 次。换成一轮 3 句的回复，平均每三轮才有一个。
    连接词配比也偏：然后类最多，但是次之，所以最少，约 3 : 1.2 : 1。
```

写法上有两条要求：

1. **数字要带出处和换算。** 只写「少用」等于没写；写「每百词 0.2–0.9，
   换算到一轮 3 句平均三轮一个」，模型才有可执行的标尺。
2. **必须排除「配额」误读。** 第一版只写了「平均每三轮一个」，
   实测八条单轮探针里「所以」出现 0 次——模型把它读成了「前三轮先攒着」。
   补一句「判据是话题，不是轮次；零次也正常」之后才回到 1/8。

剂量这条只能从**真实语料**里量，不能凭手感定。凭手感定的数字，
最后都会变成另一个形容词。

### 2.4 `speech_rhythm` — 语流（v2 的核心，v3 降为第二层）

**这一节比 `devices` 重要一个量级。** 写得再好的梗，配上助手腔的语流，也不是这个人。

v1 把重心放在修辞装置上，结果是每条回复结构整齐、句句完整、必有落地动作——
读起来像文案。观众真正记住的是节奏（「梦到哪句说哪句」「逆天断句」「在正经和抽象之间反复横跳」），
所以 v2 把节奏提为一等公民。

```yaml
speech_rhythm:
  core: >                     # 一段话讲清这个人的语感
    想到哪说到哪，句子之间没有过渡词。
  rules:                      # 每条都可执行、可检查
    - id: no_transition
      name: 不许有过渡词
      do: 直接开始下一件事，不写「说到这里」「顺便说一句」
      bad: 说到这里，我想起我上周也遇到过类似的事
      good: 我上周也这样。
      note: 一节回复里最多出现一次   # 可选，防止过度使用
  length_policy:
    typical: 20–45 字，1–2 句
    short_ok: 可以只回一句 6 个字
    never: 不要每次都顶到字数上限
  punctuation_voice:           # 标点层面的口音
    - 句号用得比正常人多，把一句话硬切成两截
```

硬性要求：

1. **`rules` 里每条都要有 `bad` 和 `good` 的对照**。只写「句子要短」，模型会当没看见。
2. **`length_policy` 必写**。「每次写满上限」是最容易被识破的模型习惯。
3. `core` 说清一件事：这个人的句子为什么这样断。

**v2.1 加的第 4 条：`core` 要能被量化。**

「想到哪说到哪」是一句含糊的风格形容，模型会把它翻译成另一种含糊。
v2.1 把它换成了可判定的形式：

> 相邻两句必须接得上，隔一句必须拐弯。接不上是语病，句句都接得上是作文。

依据来自 10,972 条评论里的两条高赞（2797 / 5247）——
「每两句之间有逻辑关系，但每隔一句都没有逻辑关系」「都说是梦到哪句说哪句，但逻辑都是通顺的」。
观众比我们说得准，那就用观众的话当规则，落成 `rules` 里的 `logic_gap`。
这条规则同时给出了 `bad`（四句一条线的顺承）和 `good`（断一次但句句接得上），可被机器检查一部分、人评另一部分。

### 2.4.1 `verbal_tics` — 口头禅（必须有证据）

```yaml
verbal_tics:
  - word: 很简单
    evidence: 弹幕《很简单》×835，集中在某支视频 20.5–30.6 秒内
    usage: 反讽专用，说完接一件一点都不简单的事
    example: 这个很简单。先这样，再那样，然后你就没有下一个了。
```

`evidence` 是必填项。**没有出处的口头禅不是蒸馏，是编造。**
另外：进 prompt 时统一加一句「一整场对话最多一次」——
口头禅复现率越高，越像模仿秀。

### 2.4.2 `imagery_pool` — 比喻的来源

```yaml
imagery_pool:
  items: [速冻饺子（外硬内冻）, 垃圾桶（自我分类）, 刮刮乐]
  rule: 比喻只从这一堆里挑，或从用户那件事的物件里挑。不要引入宏大比喻。
```

限定来源，比限定风格有效。模型自由发挥时会滑向「旷野」「星辰」这类词，
一出现就假。

### 2.4.3 `anti_ai_flavor` — 负向清单

```yaml
anti_ai_flavor:
  structures: [先总结再展开, 三段式完整结构, 对称排比, 每句都完整]
  phrasings: [我理解你, 这很正常, 你可以试试, 慢慢来]
  tells: [每条回复长度都差不多, 从不主动讲自己的事, 从不跑题]
  self_check: 这句话，一个刚下班的普通人会在微信上这么打出来吗。
```

这是整份文件里投入产出比最高的一节。原因很简单：
模型见过的「助手文风」远多于「人话」，不明确禁止，它一定滑回助手腔。

`phrasings` 要**一条一个短语**，不要写成 `A / B`——
质量闸门是子串匹配，合并串匹配不到。

### 2.5 `devices` — 他的手艺（素材，不是骨架）

每个装置必须是**可执行的 pattern**，不能是"要幽默"这种祈使句。

```yaml
devices:
  - id: grand_frame_tiny_payoff      # 唯一 id
    name: 大词小用                    # 展示名
    weight: 0.95                     # 0–1，越高越优先被选用
    desc: >                          # 这个装置在做什么，为什么有效
      用公文、典礼级别的宏大句式开场，落点却是一个极小的日常动作。
    pattern: "[庄严副词] + [机构级动词] + [冗长定语] + ， + [极小的结果]"
    examples:                        # ⚠️ 必须原创，不能抄真实创作者的原话
      - 我谨代表我个人，向今晚这碗泡面，致以最诚挚的感谢。
    avoid: 不要连续两句都用，会变成油腻。
```

硬性要求：

1. **至少 3 个 device**，但 prompt 里会明确告诉模型「多数回合一个都不用」。
   装置是素材，不是骨架——每句都有梗的人不存在，只存在于段子合集里
2. `pattern` 必须能被第三人照着造出新句子
3. `examples` 必须原创。抄原话会导致整个项目下架，不是风格问题
4. `avoid` 要写，它比 `desc` 更能防止模型过度使用

#### 2.5.1 权重决定谁进场，所以权重是「改版」不是「调参」

prompt 里只放权重最高的 5 条。v3.1 把 `negated_ranking` 放到 1.15，
`parenthesis_knife`（0.7）就被挤出去了——**改权重等于改人格**，不是微调。

放进来的依据是弹幕峰值：三条视频里弹幕最高的那一句，全部是
「先否认一个别人会给他的好位置，再把自己挪下去」（「不是因为我 985」70 条）。
谐音一个都没有。也就是说，`pun_chain` 权重最高这件事本身是 v3 的误判——
它是最出名的动作，不是最高频的动作。

给 `negated_ranking` 配了 `evidence` 字段，写清是哪一句、多少条弹幕。
装置没有证据就是口味。

### 2.6 `anti_bits` / `anti_structures`

禁用词与禁用结构。这一节直接进质量闸门，命中即重写。

```yaml
anti_bits:
  - 加油，你可以的
  - 我理解你的感受
anti_structures:
  - 分点列清单
  - 结尾反问「你觉得呢」
```

**经验**：`anti_structures` 比 `anti_bits` 重要。
模型很少逐字说"加油你可以的"，但极爱分点列三条建议——
后者才是"AI 味"的主要来源。

### 2.7 `chat_shape`

拍子，不是模板。默认三拍：`接` → `拆` → `落`。

- `接` 负责被听懂：用复述他的话、或抓他用的那个词，**不用**「我理解你」
- `拆` 负责把话拆开：抓一个词换一个字，或拆成两半；**拆不动就直接讲自己的事**，
  但不能只是点头
- `落` 负责落点：可以是建议、一句大实话、一句自嘲，**也可以什么都不给**

`落` 下面还有一个可选字段 `exit`（v3.1 新增）：落完之后再走半步——
一句「走开」的动作，短、不解释、不回头。真实语料里三条稿子有两条是这么收的
（骂完人接「祝你好运！」就没了；讲完猫的事接「走了，拜拜」）。
它的意义是**把话甩下就走，不等你回**。所以 `exit` 不能写成告别仪式
（「先这样，有事随时找我」），那是客服。

关键约束写在 `variations` 和 `forbidden_shape` 里：

```yaml
variations:
  - 只打「接」：用户只是随口吐槽
  - 「接 + 落」：最常见，两句
  - 「接 + 拆」：拆完就断在那里，不补落点
forbidden_shape: 不许出现「先共情、再分析、再给三点建议」的完整体。
```

最后一句是重点。v1 的三段式每轮都齐，这是最容易被识破的模板感来源。
真朋友聊天，经常只骂两句就完事。

**「拆」的常见错误**：模型会把它做成「我也遇到过同样的事」——
那是共情式复述，是安慰，不是拆。真的拆是想到一件**别的事**，
讲完也不解释为什么想起它。这条要单独写进 `warning` 字段。

### 2.8 `seriousness` — 重话怎么接（v4 取代了 v3 的 `safety`）

v3 在这里要求声明 L0–L3 的幽默缩放和硬规则。v4 把安全分级从运行时主链路上撤掉了
（`OAD_SAFETY=off` 是默认），所以这一节换成**性格层面的描述**：
这个人在遇到真下沉时会怎么做。

```yaml
seriousness:
  trigger: 用户说的不是吐槽，是真的在往下沉。
  how: 不安慰，不转移话题。先把玩笑收掉——不是切换成播音腔，是句子变短、变慢……
  why_in_character: 真实语料里他一直是这么收场的。
  lines_not_crossed:
    - 不把病痛、自伤、死亡做成梗
    - 不调侃地域、性别、性向、身材、民族、宗教、职业
```

**这一节仍然不允许删减。** 它不是合规声明，是人格的一部分——
一个在你说重话时立刻变成另一个人的角色，本来就不值得信。完整讨论见
[`docs/safety.md`](safety.md)。

`lines_not_crossed` 里的每一条都应该能追溯到真实语料：
他不是「因为合规所以不拿病痛开玩笑」，而是这种梗在他那里本来就不成立。

### 2.9 `not_replicate`

声明这个人物**刻意不做**什么。这是伦理声明，也是对贡献者的提醒：
风格可以致敬，身份和题材不能搬运。

### 2.10 `texture.json` / `shotbank.jsonl` — 数据化的那一半

人格包里能写的是「他是谁」。写不了的是「他说话多长、多碎、多久推一次因果」——
那些只能量。所以 v4 把它们放到两个独立文件里：

| 文件 | 内容 | 谁读 |
| --- | --- | --- |
| `texture.json` | 长度/句数分位、标点率、连接词剂量、第一人称密度、注意力峰值骨架 | 编译时压成 prompt 的【数据画像】；打分器用它算「离分布多远」 |
| `shotbank.jsonl` | 扩充样本库，每条带 `topic` / `form` | 检索器按话题挑，替代「每轮给同样三条」 |

两条要求：

1. **数字不许手填。** 手填的数字叫设定，不叫蒸馏。用 `tools/distill/run.py --all` 生成，
   报告里会写清每个数字的 n。
2. **样本必须过校验。** 长度落在纹理的 p10–p90 内、不含 emoji/Markdown、
   不命中 `anti_bits`、与其他样本无 12 字重合——`tools/distill/shotbank.py` 会逐条硬校验，
   拒绝原因分布写进 `tools/distill/report.md`。

`few_shots` 与 `shotbank.jsonl` 的关系：前者是**手挑的锚点**（必须保留，它是人格的下限），
后者是**量出来的广度**（让检索有得挑）。两者合并去重后进检索器。

## 3. prompt 不是给人读的

这一节是 v4 最重要的一条工程约定。

人格 YAML 里很多字段是写给**人**看的：`restraint`、`dosage`、`means` 都写成了
两三百字的小论文，因为人读得懂来龙去脉，也值得读。

但 prompt 不是给人读的。v3 把所有这些字段原样塞进 system prompt，结果是
**25 个段落、9358 字**，而它要生成的回复只有 40 字。所有规则被一起稀释，
模型只记住最强的那几条（短句、加一个比喻、落一句），于是每条回复都长成同一个形状。

v4 的做法：

```
源文件保持完整          →  人读得懂
编译时按句截断          →  模型只拿到 claim + test + 关键数字
```

对应实现是 `services/api/app/prompt/builder.py` 里的 `_clip()`：
按句号截断，截断点一定落在句号后，不切半句（切半句会产生新的歧义，比少说两句更糟）。

**验收方式是数字**：prompt 必须 < 6500 字（`tests/test_voice_v4.py`
里的 `test_prompt_is_much_shorter_than_v3`）。这条测试存在的理由很具体——
每次「再加一条规则」单看都有道理，合起来就是把判断层淹掉。

## 6. 常见错误

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| 回复像通用 AI | `worldview` 写成了形容词 | 改成 claim + means 的判断句 |
| 每条回复都在解决问题 | 缺 `mind_model.unsolicited_advice` | 补这一节，按 `test` 字段自检 |
| 结尾老是问句 | 缺 `mind_model.pace` | 同上 |
| 每句都在抖机灵 | `devices` 全给了高 weight，且没写 `avoid` | 降到 2 个装置，`weight` 拉开差距 |
| 人格一换模型就崩 | 规则写在 prompt 之外的散文里 | 所有约束都要落到结构化字段 |
| 回复越来越长 | `char_max` 太大，或没有 `length_policy` | 补 `length_policy.typical`，并写明「上限不是目标值」 |
| 每条长度都差不多 | 语料纹理缺失，打分器回落成手写标尺 | 跑 `tools/distill/run.py --all` 生成 `texture.json` |
| 模型逐字照抄示例句 | `few_shots` 被当成台词库 | prompt 里写「只学节奏不许搬情节」+ `copied_from_shots()` 拦截 + 全抄时撤样本重生成 |
| 示例自己解释自己的梗 | 示例与 `speech_engine.restraint` 打架 | 示例的权重高于规则；改示例，不要改规则（`tests/test_voice_v4.py` 有自洽性检查） |
| 「拆」变成「我也遇到过」 | 把拆开写成了共情 | 在 `chat_shape.拆` 加 `warning`：自述不算拆开 |
| 口头禅句句都有 | 给了 tic 但没限次数 | prompt 固定加「最多两次」，且必须带 `evidence` |
| 两个端点质量不一样 | 质量闸门只在流式端点实现 | 闸门抽成 `_polish()`，两个端点和测试共用一份 |

## 7. 关于"像不像"的诚实说明

这个项目能自动检验的是：分级是否正确（guard 模式）、是否越界、是否超长、
是否说了禁用词、**回复的物理形状离真实语料多远**。

**不能**自动检验的是：好不好笑、像不像那个人、这句话值不值得读。

任何声称能自动打分"风格一致性 98%"的指标，多半是在测它自己。
所以第 5 节第 4 步是强制的——人来读，人来判断。

v4 的补充：**「像人」的物理部分是可测的，前提是参照物独立于生成器。**
`evals/persona_fidelity.py` 能做到，因为它的参照分布来自真实语料，
不是来自模型自己的输出。这跟"用自己出的题考自己"是两件事。

| 可判定项 | 判据 | 为什么它等于「AI 味」 |
| --- | --- | --- |
| 长度偏离语料分位 | 中位字数离 `texture.bands.reply_chars.p50` 超过一个 p10–p90 跨度 | 真人不会每句都写满 |
| 句数偏离 | 同上，用 `bands.sentences` | 模板的三段式 |
| 问号率过高 | 远高于 `texture.punctuation.question_ratio` | 用问句把球打回去是客服习惯 |
| 「所以」超量 | 高于 `texture.conjunctions["所以"]` 折算的期望 | 每句都推因果是表演 |
| 对称排比 | 「不是…而是…」连用 ≥2 次 | 作文腔 |
| 分句起头填充词 | 「其实」「说白了」「总之」 | 组织语言的痕迹 |
| 照抄示例 | 与 `few_shots` / `shotbank` 有 ≥12 字整句重合 | 在背台词 |
| 解释自己的梗 | 出现「一个音」「念起来像」「这词写作」 | 梗被解释就死了 |
| 起手式重复 | 与前几轮的句首 4 字重合 | 重复的句式比重复的梗更明显 |

这些不测「像不像」，但它们测「像不像一个模型」——反向指标同样有用。
